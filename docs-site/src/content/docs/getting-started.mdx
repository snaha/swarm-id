## Basic Usage

```typescript
import { SwarmIdClient } from '@snaha/swarm-id'

// 1. Create the client
const client = new SwarmIdClient({
  iframeOrigin: 'https://swarm-id.snaha.net',
  // A new account has no drive yet. This lets it upload anyway — see the note
  // below the example.
  subsidisedGatewayUrl: 'https://api.gateway.ethswarm.org/',
  metadata: {
    name: 'My dApp',
    description: 'A demo Swarm application',
  },
  onConnectionChange: (info) => {
    console.log('Connection changed:', info.identity?.name, 'canUpload=', info.canUpload)
  },
})

// 2. Initialize (creates hidden iframe; populates client.connectionInfo)
await client.initialize()

// 3a. Option A: Use iframe authentication button
// The iframe will show a connect/disconnect button automatically

// 3b. Option B: Manual authentication with connect()
// Opens the authentication page in a new window/tab (useful for custom UI).
// Works whether or not the browser partitions the iframe's storage: the
// client picks the transport. Keep the iframe mounted for the life of the
// page — destroying it (say, by unmounting its container on sign-in) leaves
// the popup with nothing to hand the session to.
await client.connect()

// 4. Read current connection state synchronously
const info = client.connectionInfo

// 5. Upload data (requires authentication AND upload capability — a connected
//    user can still have canUpload=false if they have no postage stamp and no
//    subsidised gateway is configured)
if (info.identity && info.canUpload) {
  const result = await client.uploadData(new TextEncoder().encode('Hello, Swarm!'))
  console.log('Uploaded:', result.reference)
}

// 6. Cleanup when done
client.destroy()
```

:::note[Every new account starts without a drive]
A drive (a postage batch) is what pays for uploads, and a freshly created Swarm ID has none. So without a subsidised gateway, the first upload of every first-time user fails: `canUpload` is `false` and `uploadUnavailableReason` is `'no-stamp'`. Downloads and key derivation work regardless.

Two ways to handle it, and most dApps do both:

- **Pass `subsidisedGatewayUrl`.** Uploads from accounts with no drive then go through that gateway, which stamps them (`uploadMode` becomes `'subsidised'`). The public gateway at `https://api.gateway.ethswarm.org/` works for development and demos — see [Using the public gateway](../subsidised-gateway/#using-the-public-gateway) for its limits.
- **Send the user to add a drive.** When `uploadUnavailableReason === 'no-stamp'`, link to the identity site (`https://swarm-id.snaha.net`, Storage tab). Once the user has a drive, the session uses it in preference to any gateway.
  :::

## Configuration Options

The `SwarmIdClient` constructor accepts the following options:

| Option                 | Type       | Required | Description                                                                              |
| ---------------------- | ---------- | -------- | ---------------------------------------------------------------------------------------- |
| `iframeOrigin`         | `string`   | Yes      | Origin of the Swarm ID iframe (e.g., `https://swarm-id.snaha.net`)                       |
| `metadata`             | `object`   | No       | App metadata shown during authentication                                                 |
| `metadata.name`        | `string`   | No       | Your app's name                                                                          |
| `metadata.description` | `string`   | No       | Brief description of your app                                                            |
| `onConnectionChange`   | `function` | No       | Callback when the dApp-visible connection state changes (identity, stamp, account, auth) |

## Data Operations

> **Note:** Data operations require the user to be authenticated first. Use `client.connect()` or the iframe button to authenticate.

### Upload Data

```typescript
// Simple upload
const result = await client.uploadData(data)

// Upload with encryption
const result = await client.uploadData(data, { encrypt: true })

// Upload with progress tracking: `onProgress` is an upload option, and
// progress is counted in chunks
const result = await client.uploadData(data, {
  onProgress: (progress) => console.log(`${progress.processed}/${progress.total} chunks`),
})
```

Retrieve what `uploadData` stored with `downloadData`, or from a gateway at `/bytes/<reference>`. It is raw bytes with no manifest, so `downloadFile` and `/bzz/<reference>/` cannot resolve it.

### Download Data

```typescript
// Download by reference
const data = await client.downloadData(reference)

// Download encrypted data (reference will be 128 chars instead of 64)
const data = await client.downloadData(encryptedReference)
```

### File Operations

`uploadFile` wraps the bytes in a manifest that carries the filename, so its reference is read back with `downloadFile`, or from a gateway at `/bzz/<reference>/`. The two pairs do not cross.

```typescript
// Upload a file
const result = await client.uploadFile(file, 'myfile.txt')

// Download a file
const fileData = await client.downloadFile(reference)
console.log(fileData.name, fileData.data)
```

## A batch you were given

A postage batch (a **drive** in the identity UI) is not an identity. If someone hands you a batch id and the private key that owns it, as hackathon gift codes do, create or sign in to a Swarm ID however you like, then attach the batch: **Storage → Add drive → Use existing batch**, with the batch id and the signer key. From then on every dApp the account connects can upload with it. On a new device, an existing account is restored from its recovery phrase; the batch comes back with it.

## Local Development

```bash
# Clone the repository
git clone https://github.com/snaha/swarm-id

# Install dependencies
pnpm install

# Start both demo and identity UI
pnpm dev
```

Open http://localhost:3500 — that's it!

- Demo app runs on port 3500
- Identity UI runs on port 5500
- The account bus signaling server runs on port 5520
- No HTTPS, certificates, or custom domains required (`localhost` is a [secure context](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts))

For advanced setup (local Bee cluster, SSH tunnels for real-domain testing, known dev keys), see the [Local Development guide](../local-development/).
